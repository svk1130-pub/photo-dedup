# Changelog — Photo Dedup

Все заметные изменения проекта по версиям (новые — сверху). Подробные
разделы по каждой версии с командами проверки — в `README.md`; архитектура —
в `docs/ARCHITECTURE.md`. Версионирование: новое — minor (1.x.0), хотфиксы —
patch (1.4.x).

## 1.11.0 — тема оформления и консолидированный changelog

* **🌙/☀️ Переключатель тёмной/светлой темы** — в самом верху сайдбара.
  Применяется мгновенно (CSS поверх DOM Streamlit; `streamlit==1.45.0`
  не умеет менять тему в рантайме штатно). Тёмная тема перекрашивает
  поверхности, текст, метрики, вкладки, кнопки, поля, списки, календарь,
  диалоги, тосты и скроллбары; светлая — прежний вид приложения без
  изменений (ноль регрессии). Выбор сохраняется в адресе страницы
  (`?theme=dark|light`) — переживает обновление страницы и шарится ссылкой.
* **📄 Новый файл `CHANGELOG.md`** — сводка изменений по всем версиям
  (этот файл).
* Код движка не менялся: затронуты только `web/app.py` (тема), документация
  и версии в compose. smoke/integ/kill9 — зелёные.

## 1.10.0 — полировка очереди (пауза, причина остановки, история)

* **⏸ Глобальная пауза очереди** (`status.runner_paused`): runner не берёт
  задания (включая созревшие отложенные), выполняемое дорабатывает штатно;
  флаг в БД — переживает рестарты; кнопка «⏸ Пауза очереди» /
  «▶️ Возобновить очередь» на Мониторе; на паузе срочные queued-задания не
  блокируют кнопки запуска.
* **🛑 Причина остановки** (`jobs.stop_reason`): разделило смыслы `error`
  (про ошибки) и причину, почему задание не доработало — «остановлено
  пользователем (кнопка Стоп)», «остановлено сигналом», «отменено
  пользователем (не начато)», «прогон оборвался: heartbeat истёк».
* **🗑 Интерактивная история**: «✖» у каждой записи и «🧹 Очистить» с
  подтверждением; удаляются только завершённые (queued/running целы);
  retention `RUNNER_RETAIN_JOBS` работает как раньше.

## 1.9.0 — CLI: отложенный запуск (schedule --at/--delay)

* `docker compose run --rm engine schedule JOB --at "21:30"` /
  `--at "2026-10-10 09:00"` / `--delay 2m` — постановка заданий в очередь
  jobs из командной строки (JOB ∈ run/scan/analyze/move/undo); параметры
  команды — как CLI-флаги; `--dry-run` поддерживается. Прошедшие моменты
  отклоняются без молчаливого сдвига; uniq-индекс и single-flight — как у
  кнопок UI; runner и схема БД не менялись.

## 1.8.0 — «Своё время…»: выбор даты

* Отложенный запуск на произвольные дату+время: календарь (`st.date_input`)
  рядом со временем (`st.time_input`) в варианте «Своё время…»; прошедший
  момент — предупреждение и блокировка кнопок запуска (без молчаливого
  переноса на завтра); моменты другого года показываются с годом.

## 1.7.1 — хотфикс: задвоение «Опасных зон»

* Устранено задвоение блоков после завершения Прогона/Скан: полный rerun
  приложения (автообновление галереи) перенесён в начало фрагмент-рана,
  до генерации дельт; manual-блок подтверждения переноса показывается
  только в `move.mode=manual` (в auto скрыт — там он ни на что не влияет).

## 1.7.0 — отложенный запуск (Ф3) + автообновление галереи

* **Отложенный запуск из UI**: `jobs.scheduled_at` (TIMESTAMPTZ, NULL =
  ASAP); пресеты «Сейчас / 30 мин / 1 ч / 3 ч / сегодня 03:00 / завтра
  03:00 / Своё время…» в поясе TZ контейнера; в очереди — отсчёт до запуска
  и действия «▶️ Сейчас / ⏰ +1 ч / ✖ Отменить»; отложенное задание не
  блокирует немедленный запуск других команд; догоняющая семантика после
  простоя runner'а.
* **Галерея обновляется сама** на границе «занят → свободен» (без F5,
  без постоянного поллинга миниатюр); `TZ` в compose для web/runner/engine.

## 1.6.1 — хотфикс: кнопки очереди (KeyError: 0)

* Пул web создавал соединения с `dict_row`, а `jobs.enqueue` извлекал
  `RETURNING id` по индексу → задание не добавлялось. Теперь
  `db.first_value` агностичен к row-factory (enqueue, clean_db, scalar);
  UI даёт понятное сообщение, если таблицы jobs ещё нет.

## 1.6.0 — все команды в очереди (Ф2)

* Кнопки «🔍 Скан / 🧠 Анализ / 📦 Перенос / ↩️ Undo (с подтверждением)»
  на Мониторе — все длинные команды идут через очередь jobs → runner;
  stale-детекция из UI («⚠️ Прогон оборвался» + автоматический reap по
  протухшему heartbeat'у); retention истории очереди
  (`RUNNER_RETAIN_JOBS=200`), «💥 Очистить БД» вычищает очередь целиком.

## 1.5.0 — job-runner (Ф1)

* Таблица `jobs` в PostgreSQL: атомарный взбор `FOR UPDATE SKIP LOCKED`,
  пробуждение `LISTEN/NOTIFY`, single-flight guard, heartbeat, частичный
  uniq-индекс (одно queued-задание на команду); сервис runner (тот же
  образ, in-process, без docker-сокета); кнопка «▶️ Запустить прогон» и
  история заданий на Мониторе; «Стоп» един для CLI/runner.

## 1.4.3 — хотфикс ручного режима

* «⭐ Это оригинал» / «📋 Сделать дубликатом» не падают FileNotFoundError
  (папка группы создаётся до переноса); новый оригинал выбирается ДО
  вычисления имени папки (группа не дробится); «ℹ️» не рендерится внутри
  модального окна; подтверждение «🗑️» остаётся внутри окна (без rerun).

## 1.4.2 — UX свежей БД

* Понятный экран инициализации: UndefinedTable больше не маскируется под
  «PostgreSQL недоступен» — UI объясняет, что таблицы создаёт движок при
  первом запуске, и даёт команду `docker compose run --rm engine status`
  в копирование одним кликом.

## 1.4.1 — WHY_NO_BUTTONS

* `docs/WHY_NO_BUTTONS.md`: подробный разбор, почему «настоящие кнопки
  запуска движка из UI через docker-сокет» вредят тонкому клиенту и
  безопасности, и какие схемы корректны (очередь в БД + sidecar-раннер —
  реализована в 1.5.0); `engine.__version__` синхронизирован с релизом.

## 1.4.0 — ручные операции, undo, документация

* Кнопки-действия под каждой картинкой галереи: ⭐ «Это оригинал» /
  📋 «Сделать дубликатом» / ↩️ «Вернуть» / 🗑️ «Удалить» / ℹ️ «Свойства»

  + кнопки «↩️ Отменить всё» / «💥 Очистить БД» / «🧹 Очистить журнал»;
  `docs/` (ARCHITECTURE, LOGIC, LOGIC_EXT, UI_DESIGN).

## 1.3.0 — P2-хвост

* Атомарная запись settings.toml (tmp + fsync + os.replace); галерея без
  N+1 запросов (батч-выборка членов страницы); честные единицы скорости
  («бакетов/с» на analyze); `files.status='moved'` с идемпотентной
  миграцией; crash-recovery без «приклейки» одноимённых дубликатов
  (+ персистентность recovery `moved_to`); подсчёт кандидатов в scan —
  фоновым потоком (без блокирующего прохода).

## 1.2.0 — оригинал по времени снимка

* `keep_by=capture` (новый дефолт): время снимка из json-Takeout (sidecar
  `<файл>.json`) → файловая система (min(birthtime, mtime)) → тай-брейк по
  «копийным» маркерам имени; `size`/`pixels` сохранены. Папки групп в trash
  называются по имени оригинала; санитизация Windows/Unicode, коллизии
  `__2`; имя папки пишется в `groups.info.group_dir`.

## 1.1.0 — P0-фиксы + sha256-верификация

* `analyze` не падает OverflowError на смешанных длинах хэшей (смена
  hash_size без --force); память `_bucket_pairs`: 1331 МБ → 24 МБ на бакете
  30K (2D-чанкинг); `move --dry-run` не меняет БД ни в каких ветках;
  sha256-верификация точных копий оригинала (маркеры в плане, info.txt,
  groups.info).

## 1.0.0 — исходная версия

* CLI-движок + Streamlit-тонкий клиент + PostgreSQL (3 контейнера):
  индексация архива (scan, батчи, resume), поиск изменённых/повёрнутых/
  зеркальных дубликатов (D4-хэши imagehash), перенос дубликатов в trash
  (auto/manual, dry-run, info.txt, crash recovery), журнал events.
